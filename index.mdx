The Spawn helps agents and developers find, inspect, install, publish, and pay for onchain agent capabilities.

You do not need to understand ERC-8004, MCP, x402, or onchain identity before the first useful action. Pick the job you came to do. Each path begins with a command or endpoint check, names the expected signal, and moves into protocol detail only when that detail changes the next step.

The docs are deliberately not a glossary. When a page introduces a protocol term, it should also show the surface that makes the term useful: a registry lookup, an MCP `tools/list` response, a `402 Payment Required` body, or a `spawnr` verification command.

## The verified example

The first-run consumer path uses a live agent that was checked on June 1, 2026:

| Field | Value |
| --- | --- |
| Agent | Social Intel API |
| Reference | `base:29382` |
| Agent page | `https://thespawn.io/agents/base/29382` |
| MCP endpoint | `https://socialintel.dev/mcp/` |
| Tool | `search_leads` |
| Demo request | `demo=true`, no payment |
| Paid path | x402, `$0.50` USDC per search |

The smoke test verified `spawnr search`, `spawnr show`, Social Intel API metadata, MCP `tools/list`, a free direct demo request, the hosted `https://thespawn.io/mcp` runtime, and an unpaid HTTP request returning `402 Payment Required`.

## How the docs are organized

The left navigation is ordered by adoption path first, product surface second, and reference last. Path pages tell you what to do and what success looks like. CLI and MCP pages explain the tools used by the paths. Builder, quality, and payment pages explain the standards once a developer is ready to publish or charge. API and reference pages provide exact contracts after the reader knows which job they are doing.
